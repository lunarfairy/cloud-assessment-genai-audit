# Collateral failures of the grader mutants: diffs and dependencies

Scope: the 11 mutants (of 77) whose grading fails at least one check besides its target. The T1-T3 and DES mutants were
regenerated by `mutate.py` from `gold/` with exact text edits, because the original notebook mutants were not archived.
For every one of the 76 catalogued mutants, the regenerated mutant reproduces the archived catalogue's collateral set
exactly (0 mismatches; `mutation_results.csv`). The 15 application mutants are the archived `mutants_app/app_00..14`,
copied unchanged. APP_M01 (A01) is new. Messages are the archived graders' own output (unmodified `checks_iac.py`,
`checks_des.py`, `app_runner.py`).

Each dependency is classified as one of:

* **genuine**: the single edit really violates the second requirement as worded in the brief.
* **check design (conservative)**: the check refuses to certify something it cannot evaluate.
* **conflation**: the check tests a property that belongs to another requirement, so one fault is counted twice.
* **over-broad mutant**: the archived mutant changes more than its label says.

## T3_M11, ASG in public subnets: did the mutant change more than its label, or do the checks conflate requirements?

The reviewers doubted that this mutant should also fail T3.R1 and T3.R3. The regenerated mutant changes only the two
`VPCZoneIdentifier` entries:

```diff
--- gold/T3.yaml
+++ mutants/T3/T3_M11.yaml
@@ -212,6 +212,6 @@
       DesiredCapacity: '2'
       VPCZoneIdentifier:
-        - !Ref PrivateSubnet1
-        - !Ref PrivateSubnet2
+        - !Ref PublicSubnet1
+        - !Ref PublicSubnet2
       LaunchTemplate:
         LaunchTemplateId: !Ref WebLaunchTemplate
```

This minimal edit reproduces the catalogue's collateral set `T3.R1;T3.R3;T3.R7` exactly. The VPC, the four subnets,
the NAT gateway, the route tables and the route-table associations are byte-identical to gold. The R1/R3 failures
therefore do not require any change to subnet routing. They come from the checker. `t3_checks` defines the two subnet
roles from resource placement rather than from the network itself:

```python
pub  = alb_sn if alb_sn else [s for s in subnets if T.route_public(s)]
priv = asg_sn if asg_sn else [s for s in subnets if s not in pub]
```

Once the ASG sits in the public subnets, `priv` = [PublicSubnet1, PublicSubnet2]. The checks then report:

* **T3.R1:** "private ['PublicSubnet1', 'PublicSubnet2']: subnets in distinct Availability Zones [0, 1]". R1 fails only
  through `not (set(pub) & set(priv))`.
* **T3.R3:** "private subnets default-routed to NAT and no IGW {'PublicSubnet1': False, 'PublicSubnet2': False}".
* **T3.R7:** "'no_public_ip': False". This is because `no_public_ip` tests `MapPublicIpOnLaunch` of the ASG's subnets.

**Conclusion.** R1 and R3 are failed by check conflation, not because the archived mutant changed more than its label.
The original notebook mutant is not archived, so this cannot be proved for the original file. However, the collateral
pattern is fully explained without any extra change, and the minimal edit reproduces it exactly. The template still
contains two private subnets in different AZs (R1) and a NAT gateway with private default routes (R3), so a human
marker applying the brief would fail only R8 here.

**R7 is a different case.** Instances launched into subnets with `MapPublicIpOnLaunch: true`, from a launch template
that does not override the setting, really do receive public IPv4 addresses. That violates R7 ("does not assign public
IP addresses"), so R7 is a genuine consequence for T3_M11. The check is still imperfect. Adversarial case **ADV_T3_16**
keeps the ASG in the public subnets but adds `NetworkInterfaces: [{DeviceIndex: 0, AssociatePublicIpAddress: false,
Groups: [...]}]`. The archived grader still fails R1, R3 and R7, although only R8 is violated: the explicit interface
setting overrides the subnet attribute.

**Proposed fix (implemented in `patched_copy/tier1`, patch P14).**

* Judge R1/R3 on "structural" private subnets: subnets that are neither ALB subnets, nor routed to the IGW, nor mapping
  public IPs. Fall back to the ASG subnets only if fewer than two exist.
* In R7, accept an explicit `AssociatePublicIpAddress: false`.

With P14, T3_M11 fails R8 and R7 only, and ADV_T3_16 fails R8 only. T3_M01 and T3_M03 keep their R1/R3 detection.
P14 changed no archived model verdict (`regrade_tier1.json`), because no archived submission placed its ASG in public
subnets with otherwise correct networking.

## Other dependencies

**T1_M05 (HTTPS to HTTP; R6).** The diff changes `FromPort/ToPort 443` to `80`. R6 reports "extra inbound rules:
[tcp 80-80 from 0.0.0.0/0]". The brief's R6 says the SG must contain only the two listed rules, and an HTTP rule is not
one of them, so this is genuine.

**T1_M06 (SSH from 0.0.0.0/0; R1, R6).** The diff changes `CidrIp: !Ref AdminCidr` to `0.0.0.0/0`.

* R6 is genuine: an SSH rule from the world is not "SSH only from the administrator CIDR parameter".
* R1 is a mild conflation. The brief's R1 only asks that the admin-CIDR parameter be *declared*, and it still is. The
  check also requires it to be *used* in an SSH rule ("admin CIDR parameter used in SSH rule: False"). The double count
  is defensible, because an unused parameter does not serve its stated purpose, but it should be documented.

**T2_M05 (private subnet 1 on the public route table; R8).** The diff changes `RouteTableId: !Ref PrivateRouteTable` to
`PublicRouteTable` for `PrivateSubnet1Assoc`. R8 reports `'private_subnets': False`. R8 requires the DB subnet group to be
made of the two private subnets, and PrivateSubnet1 is now public by routing, so this is genuine.

**T3_M01 (both private subnets in AZ index 0; R8, R12).**

* R12 is genuine. RDS rejects a DB subnet group that does not cover at least two AZs, so the stack would not deploy,
  and Multi-AZ placement is impossible.
* R8 is a conflation. R8 asks for the ASG "across the two private subnets", which still holds. The check re-tests the
  distinct-AZ property that belongs to R1 (`distinct_getazs(asg_sn)`).

**T3_M03 (private default route to the IGW; R8, R12).** The diff changes `NatGatewayId: !Ref NatGateway` to
`GatewayId: !Ref InternetGateway`. Both private subnets become public by routing, so the ASG (R8) and the DB subnet
group (R12) are no longer in private subnets. This is genuine.

**DES_M01 (unknown price item; D02, D04).** The diff renames `elasticache_cache.t3.medium_hour` to the non-existent
`elasticache_cache.t3.small_hour`. D02 reports "stated proposed 581.97 vs recomputed 532.33" and D04 reports
"recomputed proposed cost 532.33 vs budget 750". Both checks are coded to fail whenever D01 finds an unpriceable item:
`... and not bad_items`. This is a conservative design choice (an unpriceable BoM cannot be certified as within budget),
not a requirement conflation. It should be stated in the paper, because D04 would otherwise pass at US$532.33.

**APP_M01 (new; photo_url renamed get_photo_url; A12, A13).** A12 and A13 call `photo_url` and cannot run without it.
This is unavoidable and genuine. A01 fails with "missing functions: ['photo_url']".

**APP_M04 (archived "case-sensitive search"; A03, A05): over-broad mutant.** The archived mutant changes more than case
sensitivity:

```diff
-    like = "%" + term.lower() + "%"
+    like = "%" + term + "%"
-        "WHERE lower(title) LIKE ? OR lower(coalesce(description, '')) LIKE ? ORDER BY id ASC",
+        "WHERE instr(title, ?) > 0 OR instr(coalesce(description, ''), ?) > 0 ORDER BY id ASC",
```

`instr()` is given the LIKE pattern `%term%`, so it searches for the literal string "%term%" and substring search breaks
altogether. That is why A05 (searching "O'Brien") also fails. A supplementary, strictly targeted mutant (**APP_S01**:
`instr(title, ?)` with the raw term) fails A04 and A03 but not A05. The A03 failure is a fixture dependency: A03 expects
"sunset" to match the title "Sunset at beach", so A03 implicitly requires case-insensitivity. The catalogue's A05
collateral is therefore an artefact of the archived mutant, and A03's is a real coupling inside the test suite.

**APP_M06 (string-built SELECT; A05).** The diff replaces the parameterised query with `... LIKE '%s' ...' % (like, like)`.
A05's quoted search term ("O'Brien") then produces broken SQL. This is the same defect as A06 reached through a different
input, so it is genuine.

**APP_M08 (key without uuid; A09).** The diff changes `key = "photos/%s/%s" % (uuid.uuid4().hex, ...)` to
`"photos/%s" % _safe_name(filename)`. A09 asserts `k.count("/") == 2` in addition to the safe name. The sanitiser is
correct, but A09 fails because of the key format, which A08 already tests. This is a conflation inside the test suite.
A proposed fix is for A09 to compare only the last path segment.
